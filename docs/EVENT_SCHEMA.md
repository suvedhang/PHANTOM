# PHANTOM Event Schema

Schema version: `1.0`

This document describes the durable incident event produced by the deterministic
rule engine and served by the API. The canonical machine-readable definition is
`packages/contracts/schema/event.schema.json`; the Pydantic model lives at
`apps/api/phantom_api/schemas.py`.

## Coordinate convention

All geometry is expressed in **normalized image coordinates** in the closed range
`[0, 1]`, with the origin at the top-left corner, `+x` pointing right and `+y`
pointing down. Normalized units are **image-space fractions, not metres**.

A bounding box is serialized as an object `{x_min, y_min, x_max, y_max}`. A
polygon is an object `{points: [{x, y}, ...]}`.

## Provenance

Every geometry-bearing value carries a provenance tag:

| Tag | Meaning |
| --- | --- |
| `observed` | Produced by a real, verified source (unavailable in demo mode). |
| `simulated` | Produced by the deterministic mock adapter. Always visibly labelled. |
| `configured` | Created explicitly by an operator (regions, rules, settings). |
| `derived` | Computed from other values (durations, counts). |

## Event object

| Field | Type | Notes |
| --- | --- | --- |
| `schema_version` | string | `"1.0"` |
| `event_id` | string | Stable unique identifier |
| `run_id` | string | Run that produced the event |
| `source_id` | string | Source identity |
| `rule_id` | string | Rule that fired |
| `rule_version` | integer | Version of the rule at evaluation time |
| `created_at` | ISO-8601 UTC | First creation |
| `first_seen` | ISO-8601 UTC | First matching observation |
| `last_seen` | ISO-8601 UTC | Most recent matching observation |
| `severity` | enum | `info, low, medium, high, critical` |
| `status` | enum | `active, acknowledged, resolved, dismissed` |
| `title` | string | Human-readable summary |
| `provenance` | enum | See provenance table |
| `is_simulated` | boolean | True when produced from simulated observations |
| `correlation_id` | string \| null | Groups related events |
| `explanation` | object | `{human, machine, generated_by}` |
| `evidence` | object | Structured evidence payload |
| `track_ids` | string[] | Tracks involved |
| `observation_ids` | string[] | Observing frames referenced |
| `evidence_quality` | number \| null | 0–1 confidence in the evidence |
| `closed_reason` | string \| null | Why the event was closed |

## Explanation

`generated_by` is always `"deterministic"`. `human` is a sentence an operator can
read; `machine` is a structured object that references only the rule
configuration and the observations that produced the event. Explanations are
generated by code, never by a language model.

## Status transitions

The allowed actions are `acknowledge`, `resolve`, `dismiss`, `reopen`, and
`annotate`. Each transition appends an entry to the event's audit trail with the
actor and timestamp.

## WebSocket surface

Live clients receive `WsMessage` envelopes: `{type, ts, payload}`. Types are
`connected`, `heartbeat`, `observation`, `run_status`, `event_created`, and
`event_updated`. The `observation` payload is described by
`packages/contracts/schema/observation.schema.json`.
